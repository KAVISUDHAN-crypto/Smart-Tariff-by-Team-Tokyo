# Smart Tariff: Smart Home Energy Optimizer (Hybrid)

INFINIX'26 problem CE-03, by Team Tokyo (Dr. NGP Institute of Technology, Coimbatore).

An Arduino measures voltage and current for two loads and a Raspberry Pi 4B shows them on a live web dashboard. Electricity cost is calculated from a slab tariff and peak/off-peak hours. Loads can be switched automatically to cut cost, and the dashboard compares the cost with and without the optimizer.

## Features

- Live voltage, current, power, energy and estimated cost for two loads (Load 1 = Fan, Load 2 = Light)
- Relay switch for each load from the dashboard
- Tariff-based cost: slab rate (chosen from bi-monthly units) x time-of-day multiplier
- ML peak-hour prediction (gradient boosting) for every hour of the day
- Three automatic modes that never run at the same time:
  - Timed periods (four Start/End periods with Fan and Light tick boxes)
  - Peak-hour auto control
  - Cheapest-hours planner for each appliance
- Manual relay control switches every automatic mode off
- Energy Optimization Comparison: Without Optimizer vs With Optimizer, with energy and cost saved
- Sensor readings logged to CSV for training future models
- Light and dark mode, works on phone and desktop

## How it works

    Arduino Uno -- USB serial (9600 baud) --> Raspberry Pi 4B (Flask app.py)
                                                  |
                                   Server-Sent Events /stream
                                                  |
                                             Web dashboard
    Dashboard switch --> POST /api/relay --> serial command "1:ON" / "2:OFF" --> Arduino relays

The Arduino prints one line per reading:

    DATA,v1,i1,v2,i2,relay1,relay2,displayedLoad

Power for each load is voltage x current.

## Hardware

- Arduino Uno
- Voltage sensor module (0-25 V DC) and ACS712 current sensor, one pair per load
- 2-channel relay module
- Raspberry Pi 4B
- USB cable between Arduino and Pi (shows up as /dev/ttyUSB0 or /dev/ttyACM0)

The sensors average the ADC readings, so they measure DC. Calibrate the zero offsets at start-up with the loads disconnected.

## Setup on the Raspberry Pi

    git clone https://github.com/KAVISUDHAN-crypto/Smart-Tariff-by-Team-Tokyo.git
    cd Smart-Tariff-by-Team-Tokyo
    pip install -r requirements.txt
    python3 app.py

Then open http://<pi-ip>:5000 in a browser on the same network.

Set the serial port and baud rate near the top of app.py if yours differ. Make sure the Pi's time zone is correct, because the schedule uses the Pi's local time:

    sudo timedatectl set-timezone Asia/Kolkata

## Machine learning

    python3 train_peak_model.py

This trains the hourly load forecast and writes peak_hours_ml.csv, which the dashboard uses to label each hour as peak, normal or off-peak.

household_load_synthetic.csv is a synthetic dataset generated by gen_csv.py. It is not real household data. Live readings are saved to CSV by the app, and update_dataset.py can be used to add them to the training data.

## Tariff

Slab rates and the peak/off-peak multipliers are placeholders. Replace them with the rates on your own electricity bill before using the cost figures. Cost is an estimate and does not include fixed charges, taxes or subsidies.

## Files

- app.py: Flask server, serial reader, relay control, scheduling and dashboard API
- templates/index.html: the web dashboard
- tariff.py: tariff calculation
- schedule.json: saved schedule
- arduino_serial.py: USB serial reader helper
- mqtt_monitor.py: optional MQTT monitor
- train_peak_model.py: trains the peak-hour model
- gen_csv.py, update_dataset.py: dataset helpers
- peak_hours_ml.csv, load_model.joblib: trained peak-hour output and model
- requirements.txt: Python packages

## Limitations

- The relay endpoint has no password, so use it on a trusted network only.
- Slab rates and multipliers are unverified placeholders.
- The sensors measure DC loads only.
